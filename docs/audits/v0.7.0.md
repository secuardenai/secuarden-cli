## Verdict and product boundary

Keep the product centered on: **Secuarden records supported AI coding activity
and makes its evidence and gaps inspectable.**

The recorder has useful foundations. Scope has expanded into separate observation,
receipt, enforcement, and risk workflows without one equally simple user journey.
Freeze expansion of these adjacent workflows. Do not remove commands or rewrite
storage to simplify the product narrative.

Local integrity verification is not proof of complete capture, authorship,
authorization, or resistance to a laptop owner reconstructing history. The CLI
does not establish a complete, remotely enforced PR governance workflow.

## Primary journey

1. Install a stable binary; use `init --repo PATH --agent claude-code`. For a
   disposable validation repository, choose repository-limited capture explicitly.
   Existing sync settings are preserved; absence of a new API key does not disable
   prior sync. Avoid changing real configuration as part of a documentation audit.
2. Follow the live-verification guide with a fresh session and exact session ID.
   Successful setup means configured/armed, not proven delivery.
3. Inspect `status`, then `session ID`; use `events` for raw deliveries and
   repository-scoped `report` for summaries. A tool commonly produces two events.
4. Run repository-scoped `verify`. Read checkpoint completeness separately.
   An intact partial record is a valid integrity result, not complete coverage.
5. Optional: inspect through `serve` or explicitly configure/retry sync. Neither
   is required for the local recorder journey.

Confusion points: multiple meanings of verification; different command scopes;
parallel tools causing partial checkpoints despite matched results; three separate
evidence stores; `policy upload` meaning local activation rather than network
upload; and CI wording that can suggest evidence exists on a clean runner.
