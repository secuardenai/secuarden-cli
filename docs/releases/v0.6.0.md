# Secuarden CLI v0.6.0

This release expands local audit workflows for Claude Code and compatible Codex runtimes, adds live capture verification and Git-backed change evidence, and makes audit verification easier to read and scope to a repository.

## Highlights

- **Repository-scoped verification:** `secuarden verify` now checks the current Git repository. Use `--repo <path>` to select another repository or `--all` for the entire local audit database.
- **Readable integrity findings:** a bounded table groups failures by session and explains hash mismatches, broken chain links, legacy coverage, and unprotected metadata. Use `--details` for all findings or `--json` for structured output.
- **Live capture verification:** `verify-live` checks whether a fresh session's tool request and corresponding result reached local storage. Status includes pending and stale verification diagnostics.
- **Git-backed evidence:** consolidated change-ledger workflows, optional independent Codex observations, and signed change receipts. Signed receipts require SaaS key registration and attempt evidence upload.
- **Local dashboard improvements:** activity summaries and evidence drilldowns for sessions, files, commands, and attention items.

## Reliability and installation

- Preserve unrelated hooks in shared matcher groups.
- Complete Claude Code pre-tool checkpoints before tool execution.
- Improve SQLite startup contention handling.
- Reject oversized hook input before parsing.
- Support historical stored hash formats while continuing to detect mismatches.
- Verify downloaded installer archives against published checksums and reject unsupported platforms.
- Run tests before publishing release artifacts.

## Upgrade notes

- **Changed default scope:** scripts that relied on whole-database verification must use `secuarden verify --all`.
- **Changed JSON exit behavior:** `verify --json` now exits with status 1 for integrity failures or empty selections. JSON retains existing integrity fields and adds scope, status, storage, and structured findings.
- **Empty results are explicit:** no matching records reports `NO RECORDS`, not verification success.
- Repository matching uses canonical Git remote identity, including other clones/worktrees with that identity. Repositories without a remote use their resolved local root. Selected sessions are verified as complete chains.
- Codex support depends on compatible runtime hooks and trust configuration. After updating, follow the setup and live-verification guides to check capture delivery.

## Scope and limitations

Integrity verification checks stored audit records, not current source files or capture completeness. Live verification confirms persisted request/result delivery; it does not establish tool success, client surface, hash integrity, or SaaS delivery. Parallel tool calls can leave repository checkpoints partial. Legacy records cannot gain complete integrity coverage retroactively.

Release builds: macOS ARM64 and AMD64; Linux AMD64. Linux ARM64 and Windows binaries are not included.
